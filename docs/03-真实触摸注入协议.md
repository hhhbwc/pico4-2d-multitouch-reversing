# 03 · 真实触摸注入协议（getevent 抓取）

这是**从设备 `getevent` 抓到的、真实的 XRShell→2D 触摸注入协议**。也是将来任何想要注入 2D 触摸都必须复刻的格式。

## 抓取方法

```sh
# 找到 virtual_input_device 的 event 节点（节点号会变）
adb shell "getevent -i" | grep -B1 "virtual_input_device"

# 监听该节点
adb shell "su -c 'timeout 25 getevent -t /dev/input/eventX > /tmp/ev.log 2>&1 &'"

# 然后在 2D 悬浮窗(Via)里操作一次触摸
```

## 一次"手指按下 + 移动"的完整序列

以 event 节点为例（type code value）：

```
EV_MSC(0004)  code=0000  value=0000003f   ← displayId(0x3f=63)。这里 = Via 当前 display id
EV_KEY(0001)  code=0145   value=00000001   ← BTN_TOOL_FINGER(0x145=325) = 1  → 触摸按下!
EV_ABS(0003)  code=0000   value=00000324   ← ABS_X = 804   (坐标 0~100000)
EV_ABS(0003)  code=0001   value=00000359   ← ABS_Y = 857
EV_SYN(0000)  code=0000   value=00000000   ← SYN_REPORT
EV_ABS ... EV_ABS ... EV_SYN ...           ← 连续 MOVE（坐标变化）
...
EV_KEY(0001)  code=0145   value=00000000   ← BTN_TOOL_FINGER = 0  → 抬起
EV_SYN
```

## 关键要点

1. **触摸用 `BTN_TOOL_FINGER`(0x145)，不是 `BTN_TOUCH`(0x14a)**。这是最容易踩的坑——用错键，系统不认触摸。
2. **每次触摸前写 `EV_MSC (code=0, value=<displayId>)`**，把触摸路由到目标虚拟 display（这里 displayId 是当前 2D 窗口，即 NS_APP[app] 的 display 号）。
3. 坐标轴是 `ABS_X / ABS_Y`（单点），范围 0~100000，被映射到 viewport 尺寸。
4. 用 `SYN_REPORT` 结束一段原子事件。

## 与多点(MT)设备的对比

- `virtual_input_device` 只有单点 `ABS_X/ABS_Y`，因此**物理上只能表达一个指针**。
- `pvr-virtual-input-*` 有 `ABS_MT_SLOT/ABS_MT_POSITION_X/Y`（多点），能表达多个指针，但被 Pico 内部专用、Touch Mapper disabled。

## 验证"多指注入在协议层可行"

用 `PvrVirtualInput::Touch(touchId=0/1,...)` 注入到 0 号 pvr-virtual-input 时，
`dumpsys input` 中出现：

```
Last Cooked Touch: pointerCount=3
[0] id=0 x=863 y=647 (isHovering=false)   ← touchId 0
[1] id=1 x=1080 y=647 (isHovering=false)  ← touchId 1
[2] id=2 ... (isHovering=true)            ← 系统激光悬浮(非注入)
```

证明：**MT 注入协议本身完全可行，能产生两个独立触摸指针**。问题只在"让它到达 2D 窗口"（见 04/05）。
