# 01 · 背景与目标

## 为什么做这个项目

PICO 4 是一款 VR 一体机，支持把 Android 应用（浏览器、视频、甚至手游）以 **2D 悬浮窗**的方式运行在 VR 空间里。

用户（Horizon）的需求：

> 想在 Pico 4 的 2D 悬浮窗里玩 MOBA 手游（如《王者荣耀》），需要**左右手柄**实现类似手机的**双指触控**操作：
> - 左手柄摇杆 = 移动
> - 右手柄摇杆 = 攻击 / 技能

但原厂 Pico 4 的 2D 悬浮窗触摸是**单点**的（激光指针 + 手柄按键），**不支持多点触控**，因此这类需要"同时移动 + 放技能"的手游基本没法玩。

## 目标

让 Pico 4 的 **2D 悬浮窗**能够接收**多点触控**（两个或者更多独立触摸指针），从而支持双指缩放、双指操作等手机常见手势。

## 为什么不能直接用现成方案

Pico 4 的 2D 悬浮窗运行在 **独立的虚拟 display（命名为 `NS_APP[包名]`）** 上，**不在主屏 display0 的 Android input 路由里**。因此：

- 标准 `adb shell input tap` / `sendevent` 注入的触摸
- Android 标准的虚拟触摸屏 / 鼠标注入

**统统到达不了 2D 窗口**。2D 窗口的触摸由 Pico 私有的一套链路单独完成。这也是整个逆向研究要搞清楚的部分。

## 成果定位

这是一个**逆向研究**项目。最终并没有得到"开箱即用"的 Mod，而是：

1. 完整摸清了 Pico 4 的 2D 触摸系统架构；
2. 捕获了真实触摸注入的精确协议；
3. 验证了 Pico 底层原生支持多指注入（`PvrVirtualInput::Touch` 多 touchId → pointerCount=2）;
4. 穷举并记录了**四条失败路径**及其原因（每一条都有实测证据）;
5. 给出了可复现的实验性代码。

它适合：对 Pico / VR 设备触摸定制、Android uinput 逆向感兴趣的开发者作为参考。
