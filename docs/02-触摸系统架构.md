# 02 · Pico 4 2D 悬浮窗触摸系统架构（完整逆向）

> 本页是整份逆向的核心。链路关系均来自**设备实测 + 静态反汇编**。

## 1. 概述

Pico 4 的 2D 悬浮窗触摸，**不是**走 Android 标准的触摸屏协议，而是由 **XRShell（`com.picoxr.xrshell`，系统 priv-app）** 通过一套**私有的 uinput 注入链路**完成。

```
手柄 (蓝牙/MCU)
   │  libpxrcontrollerservice.so 读到 trigger/rocker/touchpad
   ▼
XRShell (com.picoxr.xrshell, root)
   │  libxrshell.so: InputManager / UInput
   │      ├── create_device() 创建 uinput 设备 "virtual_input_device"
   │      └── UInput.nativeSendMotionEvent(x,y,action,displayId,deviceId) 写入触摸
   ▼
/dev/uinput  ->  /dev/input/eventN  (名为 virtual_input_device)
   │
   ▼
system_server (InputReader / 私有路由)
   │  将触摸投递到当前聚焦的 2D 悬浮窗 (NS_APP 虚拟 display)
   ▼
2D 应用 (Via 浏览器 / 手游 / 相册 ...)
```

## 2. 关键设备

设备节点号会随重启变化，**用 `getevent -i` 按名字识别**。

| 设备名 | 数量 | 能力 | 作用 |
|---|---|---|---|
| `virtual_input_device` | 1 | **单点** ABS_X/ABS_Y (max=100000) + D-pad 键 + `BTN_TOOL_FINGER` + `BTN_TOUCH` + `INPUT_PROP_DIRECT` | **2D 悬浮窗触摸**（由 XRShell 创建） |
| `pvr-virtual-input-0~4` | 5 | **多点** `ABS_MT_SLOT max=9` + `ABS_MT_POSITION_X/Y` + `INPUT_PROP_DIRECT` | Pico 内部（vrshell/socialhome/主屏）专用，平时 Touch Mapper 多为 disabled |

### 2.1 `virtual_input_device`（2D 触摸，重点）

由 XRShell 的 `libxrshell.so` 原生函数 `create_device()`（符号 `_Z13create_devicev`，地址 0x1f24fc）创建。

- **bus = BUS_VIRTUAL (0x0006)**、vendor=0x1234、product=0x5678、name=`virtual_input_device`
- 完整 KEY 集（25 个键）：`001c 0067 0069 006a 006c 0072 0073 0074 008b 009e 00ac 00c9 0130 0131 0133 0134 0145 014a 0161 0244 02c9 02ca 02cb 02cc 02cd`
- ABS：`ABS_X (0x00)`、`ABS_Y (0x01)`，max=100000
- 系统识别为：`touchScreen` + `direct` + `multi-touch`（尽管物理上只有单点坐标轴）
- **viewport 动态跟随当前聚焦的 2D app**（即 NS_APP 虚拟 display）——这是"2D 触摸能到窗口"的关键行为

> ⚠️ 设备节点号不固定（重启后 event2/event4/event5... 都出现过），务必用 `getevent -i | grep name` 定位。

### 2.2 `pvr-virtual-input-0~4`（Pico 内部 MT 设备）

由系统服务 `/system/bin/virtual_input`（注册 binder `virtual_input`，持有 5 个 /dev/uinput fd）创建。

- 每个都是原生多点：`ABS_MT_SLOT max=9`、`ABS_MT_POSITION_X/Y max=32767`、`ABS_MT_TRACKING_ID`、`ABS_MT_PRESSURE`、`INPUT_PROP_DIRECT`
- 通过 idc 的 `touch.displayId` 绑到特定虚拟 display：`pvr-virtual-input-1 → vrshell`、`pvr-virtual-input-2 → socialhome`、`pvr-virtual-input-0 → 无绑定(主屏)`
- 平时 `Touch Input Mapper (mode - disabled)`，viewport displayId=-1 —— 触摸不投递

## 3. 服务端与客户端库

| 库 | 作用 |
|---|---|
| `/system/lib64/libvirtualinput.so` | **EvdevInjector**：真正写 uinput 的库，原生支持多指（`ConfigureMultiTouchXY` / `ConfigureAbsSlots(9)` / `SendMultiTouchSlot/XY/Lift`） |
| `/system/lib64/libvirtualinputclient.so` | `PvrVirtualInput` 客户端：`pvrVirtualInputCreate/Destroy/Touch/SendKey`，`Touch(touchId,x,y,pressure,action)`，touchId 天然支持多指 |
| `/system/lib64/libpxrcontrollerservice.so` | 手柄→触摸转换（引用 libvirtualinputclient，读 trigger/rocker/touch_ax/touch_by/x/y） |

**关键点**：`PvrVirtualInput::Touch` 的 binder Parcel 序列为
`writeInt32(touchId) + writeFloat(x) + writeFloat(y) + writeFloat(pressure) + writeInt32(action)`，
**touchId 独立打包，天然支持多指**。服务端 `VirtualInputEvdev::Touch` 按 touchId 索引独立的 184 字节状态条。

## 4. XRShell 端（libxrshell.so）关键符号

| 符号 | 地址 | 作用 |
|---|---|---|
| `_Z13create_devicev` | 0x1f24fc | 创建 `virtual_input_device`（单点）并返回 fd |
| `_Z17update_display_idii` | 0x1f27f4 | 写 `EV_MSC`（type=4, code=0, value=displayId）关联触摸到指定 display |
| `_Z16update_device_idii` | 0x1f2900 | 写 `EV_MSC` 关联 device id |
| `Java_..._UInput_nativeCreateDevice` | 0x1f2a3c | JNI：调 `create_device()`，返回 fd |
| `Java_..._UInput_nativeSendMotionEvent` | 0x1f2c60 | JNI：写触摸（单点 ABS_X/Y + BTN_TOOL_FINGER） |
| `InputManager::InjectMotionEvent` | 0x1c86d4 | 注入触摸到 Panel（2D 窗口） |
| `InputManager::handleInjectMotionEvent` | 0x1c7474 | 处理注入触摸 |

## 5. Java 层（XRShell 反编译）

```java
// com.picoxr.xrshell.event.UInput
public native int  nativeCreateDevice();
public native boolean nativeSendKeyEvent(int,int,int,int);
public native boolean nativeSendMotionEvent(int,int,int,int,int);
```

`nativeSendMotionEvent` 5 个 int 参数在 JNI 层映射：
- a0 = x, a1 = y, a2 = action, a3 = displayId, a4 = deviceId

## 6. system_server 侧

- `com.android.server.input.ExtInputManagerServiceImpl.getVitualInputDevice(int)`：遍历 input 设备，按**名字** `"virtual_input_device"` 返回匹配的 InputDevice（供 XRShell 使用）。
- 触摸路由到 2D NS_APP display 的**主动关联**发生在 **XRShell 原生流程内**（这是最终死结所在，详见 `04` / `05`）。
