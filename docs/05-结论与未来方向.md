# 05 · 结论与未来方向

## 最终结论

**PICO 4 的 2D 悬浮窗触摸，在出厂设计层面就是"单点 + 由 XRShell 原生流程独占路由"。**

要让它支持多点触控，核心矛盾是：

> - 能表达多指的设备（`pvr-virtual-input-*`、自建 MT 设备）**都不被路由到 2D 窗口**；
> - 被路由到 2D 窗口的设备（`virtual_input_device`）是**单点**；
> - 让"被路由到 2D 的设备"变成多指，只能在 **XRShell 原生 `create_device()` 流程内**改动 —— 而这条流程被系统深度绑定，外部 hook 必然绕过。

当前固件（5.13.x）、当前设备环境下，**没有低成本的外部注入方案**。

## 已确认可行的部分（重要资产）

即使最终 Mod 没有做成，以下**已经过验证**、可复现：

1. **Pico 底层原生支持多指**：
   - `libvirtualinput.so::EvdevInjector` 原生配置了 `ABS_MT_SLOT max=9`；
   - `libvirtualinputclient.so::PvrVirtualInput::Touch(touchId,...)` touchId 独立打包；
   - 实测 `Touch(touchId=0/1)` → input 层 `pointerCount=2/3`。 ✅

2. **真实触摸注入协议**（`docs/03`）：`EV_MSC(displayId)` + `BTN_TOOL_FINGER` + `ABS_X/ABS_Y`。

3. **让自建设备"看起来像原设备"的三个根因**（`docs/04` 路径 3）：
   - bus 必须 `BUS_VIRTUAL` → 否则 `isExternal=true`
   - KEY 集合必须补全 → 否则 `Sources` 不匹配 `0x1703`
   - `INPUT_PROP_DIRECT` 等属性要与原设备一致

4. **uinput / Xposed / Magisk overlay 的完整操作链路**（见代码与命令）。

## 已排除的成因（完整清单）

`ABS_MT`、`INPUT_PROP_DIRECT`、vendor/product/bus、KEY 集合、`EV_MSC` 注册、`EV_MSC` 的 displayId 值、进程归属（root/host）、创建时机 —— **全部确认不是"路由到 2D"的成因**。

唯一未解决的：**XRShell 原生 `create_device()` 流程内的"路由注册"动作**。

## 未来可能的攻克方向（供参考，未实现）

1. **原生二进制注入 / ELF patch**
   在 `<libxrshell.so>: create_device()` 的 ABS 配置后、`UI_DEV_CREATE` 前，追加注册 `ABS_MT_SLOT` 等，然后重打包 XRShell 用 Magisk overlay。
   ⚠️ 实测该 `.so` **整个 .text 段无可用代码空洞**（无 NOP/零填充 padding），需要做 ELF 段注入（追加可执行段 + 改程序头/动态表）。风险高、工程量大、不保证成功。

2. **找到那条"路由注册"调用并复刻**
   反汇编 `InputManager::InjectMotionEvent`、`Renderer::setViewPort`、全局 `currentDisplayId`，定位 XRShell 究竟调用哪个接口把 `virtual_input_device` 绑定到 NS_APP display，然后在 XRShell 内复刻。
   ⚠️ 本质仍是"在 XRShell 进程内执行额外原生代码"，同样需要 hook/注入 XRShell 原生层。

3. **引入通用 inline-hook 库（Dobby）**
   当前设备**没有 Dobby**，只有 LSPlant/`liboat_hook`（面向 ART 的），无法对纯 C 符号 `create_device` 做通用 inline hook。
   若能编译并注入一个 Dobby，则可更可控地 hook `create_device` 而不绕过原生流程。

4. **pvr-virtual-input 的 display 动态绑定**
   研究 Pico 是否能让 `pvr-virtual-input-*`（MT 设备）在运行时绑定到任意 NS_APP（而不只是 vrshell/socialhome），以及为何其 Touch Mapper 在非宿主 display 下是 disabled。
